# Sync 5 Worker API

Base URL: `https://sync.multiprompt.dev` (staging: `https://sync-staging.multiprompt.dev`). JSON requests use `Content-Type: application/json`. All routes require `Authorization: Bearer <Access OIDC JWT>` as before. Except where noted, `Authorization: Device <deviceId>.<secret>` also works; device secrets are returned once and must be stored encrypted on the laptop. A revoked device gets 401 immediately on its next request. Never send the device key to another account. `X-MP-Client: desktop/<numeric.version>/<arch>` is recommended on desktop requests; builds below `MIN_DESKTOP_VERSION` get 426. Android and older clients without this header continue to work.

- `POST /devices`: Bearer only, no body. 201 `{ "deviceId": "uuid", "secret": "base64url-32-byte-key", "accountId": "oidc-sub" }`. Save the secret immediately. The server stores only its SHA-256 digest.
- `GET /devices`: Bearer or Device. 200 `[ { "deviceId": "uuid", "createdAt": "ISO-8601", "lastSeenAt": null, "ackedSeq": 0, "revokedAt": null } ]`. Timestamps become strings when populated; secrets never appear. `lastSeenAt` updates at most once per ten minutes.
- `DELETE /devices/:deviceId`: Bearer or Device from the same account. 200 `{ "revoked": true }`; 404 for unknown, already revoked, or another account's device. Self-revocation is allowed.
- `GET /changes?after=<seq>&wait=25&limit=500`: Bearer or Device. Required nonnegative integer `after`, optional `wait` 0..55 seconds (default 0), optional `limit` 1..500 (default 500). 200 `{ "head": 42, "accountId": "oidc-sub", "more": false, "changes": [{ "seq": 42, "recordId": "tab", "entityId": "opaque-id", "revision": 2, "tombstone": false, "payload": "sealed-text" }] }`. Empty response after timeout has `changes: []`. `more: true` means fetch again using the last returned `seq`; always page using that seq, not `head`. The feed contains the latest version per entity, not intermediate history. New writes get strictly increasing account-wide seq, including writes through legacy PUT. Old pre-migration rows have seq 0 and remain available from legacy `/records/:recordId?since=0`. Device calls record `ackedSeq` as the maximum of prior ack and `after`. Long polls recheck head every 1.5 s (3 s for wait=55), and can return early when a write arrives.
- `POST /batch`: Bearer or Device. `{ "ops": [{ "recordId": "tab", "entityId": "opaque-id", "expectedRevision": 0, "tombstone": false, "payload": "sealed-text" }] }`, 0..50 ops. Success 200 `{ "head": 1, "results": [{ "revision": 1 }] }`. If any op conflicts, 409 `{ "head": 1, "results": [{ "conflict": { "entityId": "opaque-id", "revision": 1, "tombstone": false, "payload": "sealed-text" } }] }`. Results match input order. Nonconflicting ops still commit atomically with sequence allocation. A missing record with a nonzero expected revision conflicts against `{ "entityId": "...", "revision": 0, "tombstone": false, "payload": null }`. Tombstones with null payload retain the last sealed payload. The server never decrypts payloads; seal for `expectedRevision + 1`, then re-seal after a conflict.
- Existing `GET /records/:recordId?since=<revision>` and `PUT /records/:recordId/:entityId` retain their existing JSON contract and revision-only responses. Both accept Device or Bearer. `GET /vault` accepts Device or Bearer; `PUT /vault` remains Bearer only. No legacy JSON response gains new fields.

Errors: 400 `{ "error": "..." }` for malformed inputs; 401 `{ "error": "..." }` for absent, expired, invalid or revoked credentials; 403 for service-token headers; 404 for missing resources; 409 for revision conflicts; 426 `{ "error": "minimum desktop version", "minDesktopVersion": "0.28.670" }` when configured; 503 `{ "paused": true }` on `/changes` and `/batch` if `SYNC_PAUSED=true` (or `1`) or `sync_account.paused=1`. A paused laptop should retry after 15 minutes. Legacy `/records` and `/vault` stay available during the pause.
