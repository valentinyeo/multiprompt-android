## Cause

The journey and its fixture use the legacy queue contract. The fixture prints a busy terminal and reads raw terminal input, but does not control the canonical message worker. Modern dispatch therefore tries to send into a terminal simulator which cannot perform the real terminal editing/handoff protocol. The three rows fail before cancellation is exercised.

Separately, the recipe asserts Queued/Cancelled/Delivered labels that the shared-message projection intentionally does not render. Cancelled canonical rows disappear. PR #389 (`9363b8b2`, 2026-11-16 22:53 UTC) already updated the sibling `chat-queued.md` fixture and assertions to this contract, but left `chat-cancel.md` behind. Restoring labels or retrying cannot repair the fixture.

## Repair and limits

The fixture now owns its worker lock while holding dispatch, as the existing queued-message fixture does. It uses the bundled canonical store, dispatch and connector, replacing only the terminal handoff with the disposable provider. It never fabricates queued/cancelled/started rows or acceptance facts. Holding fixture-controlled deadlines models a paused provider; it is not an app timeout change.

The phone still submits all three messages and cancels the exact middle message through its real long-press menu. Read-only host proof checks identities, attempts, states and transcript-backed connector facts. Before release, it requires zero receipts and byte-identical terminal captures. After release, only first/third receipts may appear, in order, with visible replies and no cancel action on a started message.

No APK source changes. This is a verification-tooling repair, not an Android bug fix. The product parent-red rule does not apply; two independent exact-head hosted emulator runs are required. Full `tools/check.sh` phases run on GitHub through `test.yml`.
