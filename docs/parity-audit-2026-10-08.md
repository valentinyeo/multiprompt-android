# Agent-chat feature parity (read-only source audit)

Scope: current local implementations, not live Windows/Android QA. Neither repository was edited.
Desktop references are relative to `~/projects/zigshell`; Android references are relative to `~/projects/multiprompt-android/app/src/main/java/dev/multiprompt/companion`.
`H` below means desktop `tools/agent-notifications/mp_complete.py`; `D` means desktop `src/main.zig`. These abbreviations also apply to `H:line` / `D:line` citations.
**Key distinction:** sharing tmux hosts does not mean sharing a chat API. Desktop prefers structured Claude/Codex JSONL transcripts; Android reconstructs text from terminal captures. Desktop still scans its attached Windows console for live UI state and fallback chat.

## Five biggest Android adoption gaps (priority order)

1. **Use structured transcripts for Claude/Codex chat.** Adopt desktop role/Markdown/timestamp parsing and SID-bound cache, retaining raw tmux for unsupported agents and live controls. This removes dependence on screen overlap, wrapping and TUI paging for recent conversation reads (`D:30503`, `:30690`; Android `reader/SessionReaderConnection.kt:313`). Do not call desktop's bounded window “full history.”
2. **Make delivery explicit and durable.** Adopt per-message states, persistent host/session outbox, safe FIFO flush, input-row Enter verification, explicit retry on uncertainty, and a distinct “queued inside Claude” state/action (`D:32964`, `:33207`, `:34134`). Android's local echo and SSH exit/completedActions currently cannot establish agent receipt (`reader/SessionReaderConnection.kt:86`, `:345`). Transcript matching helps but is not an exactly-once delivery protocol.
3. **Make needs-input and archive return event/content-based.** Apply desktop DONE/notification plus working/new-content guards to Android's session list/Waiting release; stop relying on session_activity for new-reply unread detection (`D:54961`; Android `MainViewModel.kt:443`, `:506`). Reader hook state already exists: reuse it for readiness, but durable completion identity/content evidence is still needed for unread; an idle state alone is not a new completion.
4. **Persist the actual conversation identity before dissolve.** Follow desktop's saved/resolved SID behavior instead of Android's newest-in-folder Claude selection, which can choose another live conversation in the same project (`D:30573`, `:17195`; Android `ssh/TmuxCommands.kt:233`). Keep Android's fresh tmux restore names; extend exact-ID resumes to Codex rather than copying desktop's Claude-only resume command (`model/DissolvedSession.kt:35`).
5. **Add reply speech and a hands-free conversation loop.** Dictation already exists; the missing desktop behavior is replay/read-aloud and automatic listen/send/wait turns with interruption/safety handling (`D:34796`, `:14737`; Android `ui/MultipromptApp.kt:2410`). Implement mobile audio/lifecycle controls; `--serve` would supply reply text, not microphone/TTS functionality.

## Could Android reuse mp_complete.py --serve?

**Yes, for structured transcript reads and slash/skill discovery—not as a replacement for the entire backend.** Desktop already launches `python3 ~/.local/share/zigshell/mp_complete.py --serve` over a persistent, non-PTY SSH exec channel (`D:20472`). It is stdin/stdout, not HTTP/WebSocket; Android can add an exec-channel client alongside its existing SSH snapshot stream (`ssh/SshRepository.kt:138`).

- Send six TAB-separated fields: `request-id, op, agent, session-or-token, cwd, argument`; receive `@mp` header, `M` role/timestamp/base64-text rows for transcripts, and `@@MP_END@@` (`H:566`, `:608`, `:659`). Keep request correlation, UTF-8/base64 decoding, size limits, identity checks and reconnect/backoff.
- First read can be `id\ttranscript\tclaude\ttmux:NAME\t-\t-`; server returns resolved SID/agent/name. Persist SID and known cwd; subsequent reads use `id\ttranscript\tclaude\tTOKEN\t/CWD\tSID`. Unchanged version returns `same` without rows (`H:566`, `:596`; desktop parser `src/chat_transcript.zig:53`). Codex is the other allowed agent.
- Install helper/dependencies under each SSH account on each host. Transcript op reads existing JSONL and Linux /proc/tmux metadata, without invoking an agent. Claude PID metadata gives an exact ID when present; cwd-newest Claude/Codex fallback can still be ambiguous, so reuse is not a blanket identity guarantee (`H:481`, `:526`).
- Keep tmux for send/Enter/interrupt/model dialogs and other agents (Hax/Pi/Kimi/Cursor/shell); helper accepts only Claude/Codex. Keep `tab-state.json` / notify data for lifecycle, ETA state for countdowns, and local host/read/archive/outbox stores. `--serve` has no send, unread, archive, host-list or voice operation (`H:615`).
- Smoke proof: one `--serve` process handled Claude ping → missing transcript → Codex ping with three correctly correlated/end-framed responses. This verifies stdio reuse mechanics, not Android integration or live-host/device behavior; gate evidence is in `GATES.md`.
